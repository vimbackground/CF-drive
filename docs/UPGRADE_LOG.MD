# CF-drive 升级记录

本文件记录每个已发布版本的主要变更，供管理员判断升级影响、安排部署和核对实例版本。

## 版本管理规则

- 使用语义化版本号 `主版本.次版本.修订版本`：不兼容变更升级主版本；新增向后兼容能力升级次版本；缺陷修复升级修订版本。
- 每次发布必须同步更新 `package.json`、`version.json`、`worker.js` 中的 `CF_DRIVE_RELEASE` 和本文件。
- 已部署实例可访问 `GET /api/version`，核对 `version`、`versionCode` 与 `releaseDate`；该接口不包含任何配置或凭据。
- 升级前应先运行 `npm.cmd run verify`，再依次部署 A、B。涉及 Mirror 的版本必须让两端运行同一版本后再执行灾备演练。

## 2.1.0 — 2026-09-26（当前）

### Release 描述

**新增**

- Stripe 容量模式与固定 A/B Mirror 容灾模式；受管节点支持加密凭据、健康检查、轮换、排空、归集和持久化迁移。
- Mirror 覆盖普通文件、multipart 文件和分布式分片双写，并提供 scrub、repair、双向转换、加密恢复快照和人工 B 接管。
- 网页“灾备与恢复”入口：A 可执行镜像、密钥、快照和作业操作，并直接跳转 B 恢复页；B 可导入离线私钥执行人工接管。

**修改**

- 文件类型和存储节点管理图标改为完整本地 Unicode 映射，不再依赖远程图标字体。
- 版本信息统一由 `package.json`、`version.json`、Worker 常量和 `GET /api/version` 提供。

### 升级注意事项

- A 与 B 必须同时部署本版本，B 的 `/recovery` 页面才会在受管状态下可用。
- 恢复私钥仍必须离线保管；只把不含 `d` 字段的公钥登记到 A。
- 手动恢复快照不等同于每笔事务自动同步，升级后仍应完成真实跨账号演练。

## 2.0.0 — 2026-09-15

### Release 描述

- 建立全新部署基线：Cloudflare Workers、R2、D1 虚拟文件系统与首次所有者认领。
- 提供网页文件管理、目录操作、受控分享、上传下载、预览、WebDAV 和本地回归测试。
- 提供 GitHub 自动发布、部署安全手册和基础审计文档。

## 1.0.0 之前 — 历史原型阶段

### Release 描述

- 以单实例网盘功能和界面探索为主，没有形成当前的所有者认领、R2/D1 虚拟文件系统和发布治理基线。
- 不提供到 2.x 的数据迁移或配置兼容承诺；新部署应从 2.0.0 基线及之后的版本开始。
